## 写入本项目知识库的建议

对应 `knowledge_articles` 表字段（`migrations/0001_init.sql`）：

| 表字段 | 建议取值 |
| --- | --- |
| `article_code` | 直接用上表编号（`JD-PS-001` 等），全局唯一、可回溯 |
| `category` | 建议二级分类，如 `配送-发货与签收`；一级大类只 4 个，直接用会丢失检索粒度 |
| `title` | 问题标题原文（问句形式，利于检索命中） |
| `content` | 答案正文；建议末尾追加 `原文：<URL>` 便于溯源 |
| `keywords_json` | 标题分词 + 正文高频词（如「运费」「拒收」「发票」），建议 3–8 个 |
| `source` | 原文 URL |
| `status` | 先 `draft`，抽样复核后再 `published` |

入库前需要人工确认的点：

1. **时效性**：部分答案含具体时效、运费、上门取件收费标准，页面本身可能已过期（部分正文末的更新日期是 2017–2019 年），入库前按业务现状核对。
2. **无正文 2 条**：`JD-PS-050 配送服务查询`（正文是内嵌查询工具 iframe，建议登记为工具入口）、`JD-SH-096 30 180退换货险产品说明`（正文只剩日期，疑似已下线）。
3. **规则类长文**：售后细则最长约 4800 字（发票制度说明、三方售后细则），建议整篇入库、不要切片，否则检索会断章。
4. **自营/三方成对**：「售后政策（自营）」与「售后政策（三方）」是同一问题两套规则，检索时必须带渠道标识，否则容易答错对象。
5. **版权**：内容版权归京东，仅建议作内部检索参考，不要对外原样发布。
